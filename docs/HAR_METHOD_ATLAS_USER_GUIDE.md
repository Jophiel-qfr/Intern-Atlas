# HAR Method Atlas 使用指南

## 1. 这个工具能做什么

HAR Method Atlas 面向可穿戴传感器人体行为识别（Wearable Sensor Human Activity Recognition）研究，帮助你梳理“方法是怎么演化的”：

- 找到一篇论文的前置候选（references）和后续候选（citations）。
- 读取本地 PDF，查看带章节、页码和位置的论文原文。
- 比较论文 A 与 B，分析保留、修改、替换、新增或移除了哪些组件。
- 查看作者想解决的问题、声称的贡献、实验依据和局限性。
- 回到原始证据核验结论，并保存历史、导出研究笔记。

它不能自动替代论文阅读。候选排名只是阅读优先级；“引用了某篇论文”不等于“继承了它的方法”。模型给出的关系也需要你结合原文核验。

论文发现位于首页：`http://127.0.0.1:8000/`。在“论文发现”选择 OpenAlex 或 Semantic Scholar，输入完整标题、DOI 或该来源的论文 ID，点击“查找论文”。如果出现多个匹配结果，先确认目标，再点击“查找前置与后续论文”。可以勾选候选并导出 JSON。

默认只找一层，前置和后续各 30 条，单侧最多 50 条；不自动递归扩展或下载全文。OpenAlex 支持 Work ID/URL；Semantic Scholar 还支持 arXiv ID。需要分析的 PDF 仍由你自行放入本地目录。

## 2. PDF 放在哪里

从 `app` 目录看，默认路径是：

```text
../data/papers/
```

Windows 项目布局示例：

```text
HAR-Method-Atlas\
├─ app\                 代码
├─ env\                 已有 Python 环境
├─ data\
│  ├─ papers\            放入论文 PDF
│  ├─ analyses\          已保存的分析结果
│  └─ smoke.db            启动服务使用的数据库示例
├─ cache\
└─ logs\
```

把 PDF 直接放进 `HAR-Method-Atlas\data\papers\`，不要放进 `app`，也不要放在 `papers` 的子文件夹中。页面只列出该目录直接包含的 PDF，不扫描整个磁盘。目录不存在时显示空列表；可以手动创建。

如果已配置 `INTERN_ATLAS_DATA_DIR`，实际目录是该数据目录下的 `papers` 和 `analyses`。`--db` 只选择图数据库，不会改变 PDF 或历史保存目录。默认数据目录由源码位置计算，不随 PowerShell 当前目录变化。

## 3. 如何启动

打开使用已有项目环境的 PowerShell，进入 `app` 目录。下面的命令要求 `..\data\smoke.db` 已存在，并且是本项目创建的数据库：

```powershell
intern-atlas serve --db ..\data\smoke.db --host 127.0.0.1 --port 8000
```

如果已有数据库名称不同，将 `--db` 改成那个文件的路径。如果还没有数据库，可先用自带示例创建一个，以下命令不调用 LLM：

```powershell
intern-atlas build --input examples/papers.txt --out ..\data\smoke.db --no-llm
```

随后运行上面的 `serve` 命令。示例数据库只用于启动现有服务，不会自动导入你的本地 PDF 或生成方法演化分析。

浏览器打开：

```text
http://127.0.0.1:8000/local-papers
```

PowerShell 窗口需要保持运行。结束服务可以在该窗口按 `Ctrl+C`；下次使用重新启动即可。历史记录保存在磁盘上，不会随服务关闭消失。

如果提示找不到 `intern-atlas`，先确认使用的是已有项目环境。也可以从 `app` 用同一个环境中的 Python 启动：

```powershell
..\env\python.exe -m intern_atlas.cli serve --db ..\data\smoke.db --host 127.0.0.1 --port 8000
```

无需创建第二个环境。

## 4. 如何比较两篇论文

- **Paper A / Source**：基础方法、较早论文，或你希望作为比较起点的方法。
- **Paper B / Target**：想研究它如何变化的后续论文。

两者不能选择同一个 PDF。A → B 是分析方向，不仅是发布时间排序。

操作流程：

1. 在“本地论文”页面选择源论文 A 和目标论文 B。
2. 点击“预览分析证据（免费）”。
3. 检查两篇论文的证据覆盖情况、数量和提示。
4. 必要时展开详细证据，确认原文和章节识别正确。
5. 决定是否点击“调用 LLM 分析”；确认费用提示后才发送请求。
6. 先看关系、状态和方法变化，再按需展开“查看依据”。

换了论文对以后，需要重新预览。预览不会调用 LLM，也不会自动触发分析。

## 5. Preview 怎么看

每篇论文分别显示覆盖情况：

| 覆盖项 | 含义 |
| --- | --- |
| 概述 ✓ | 选中了摘要、引言、相关工作或背景文字 |
| 方法 ✓ | 选中了方法章节的文字 |
| 实验/结果 ✓ | 选中了实验或结果章节的文字 |

✓ 表示上下文里有这一类证据，不表示论文内容已被完整验证，也不保证可以确认方法继承关系。

`S001`、`S002` 等是源论文证据（Source evidence）；`T001`、`T002` 等是目标论文证据（Target evidence）。编号在当前证据上下文内有效，换了输入后不要把旧编号当成新编号。

默认每篇最多 20 个证据块、14,000 个正文字符，两篇合计最多 28,000 个正文字符。字符数不是模型 token 数，也不包含完整 prompt 的所有字符。选择器会尽量兼顾概述、方法、实验/结果，并保留适合两篇论文比较的段落。

详细证据默认折叠。平时不需要逐条读；发现覆盖缺失、章节异常或结论可疑时再展开。预算导致跳过部分段落是正常现象，提示会记录；这不代表论文中不存在相关内容。

## 6. 分析结果怎么理解

### 分析状态

| 内部值 | 页面含义与阅读建议 |
| --- | --- |
| `confirmed` | 已确认：现有证据较充分地支持这次关系判断，仍建议核对关键原文 |
| `probable` | 较可能：证据支持该关系，但比较细节还不完整 |
| `uncertain` | 待判断：有相关证据，但不足以作出可靠判断 |
| `insufficient_evidence` | 证据不足：目前无法确定方法关系，关系类型为空是正常结果 |

LLM confidence 高，不代表最终一定是 `confirmed`。这个数值是模型给出的估计，不是经过统计校准的正确率。程序会检查证据编号、证据来源和论文角色；缺少必要比较证据时可能将状态降为 `uncertain`，非法证据引用则可能直接使分析失败。本地校验也不能替代对结论语义的人工核验。

### 关系类型

| 内部值 | 含义 |
| --- | --- |
| `extends` | 在原方法基础上增加组件或能力 |
| `improves` | 核心方法基本保留，主要改善性能、效率或鲁棒性 |
| `replaces` | 用另一组件或机制替换关键部分 |
| `adapts` | 将既有方法适配到新场景、数据或任务 |
| `combines` | 明确组合多个既有方法或组件 |
| `uses_component` | 使用了某个组件，但不足以确认整体方法延续 |

继承、修改、新增、移除等摘要帮助你快速阅读；`method_changes` 提供更具体的组件变化。其中 `inherited` 是保留，`modified` 是调整，`replaced` 是替换，`added` 是新增，`removed` 是移除。

没有直接支持的字段可以为空。如果没有真正比较 A/B 方法的实验依据，“实验依据”为空比填入普通数据集或性能描述更合理。

## 7. 查看依据

在结论或具体方法变化旁展开“查看依据”。每条证据提供：

- 来自哪篇论文。
- PDF 页码和其他位置，方便定位；PDF 页码从 1 开始，可能不同于论文印刷页码。
- 章节。
- 原始 quote。

英文论文的 quote 保持英文；原文不翻译、不由模型重写。模型只能引用 `Sxxx/Txxx`，最终 quote 由程序从实际证据上下文取回。

论文标题、模型名、数据集名和缩写也保留原文。证据较多时可以只展开当前存疑的结论，无需一次展开全部正文。

## 8. API 费用

以下“免费”指这些操作不产生本工具的 LLM 调用费用：

| 免费操作 | 是否需要外部网络 |
| --- | --- |
| 打开本地网站、查看 PDF 列表 | 不需要 |
| PDF 解析、查看原始证据 | 不需要 |
| Preview、覆盖概览、展开详细证据 | 不需要 |
| OpenAlex discovery | 需要访问 OpenAlex；不调用 LLM，服务方限额由其管理 |
| 查看历史结果、刷新页面 | 不需要 |
| JSON / Markdown export | 不需要 |

Semantic Scholar discovery 同样不调用 LLM，但依赖外部服务的访问和限额。

**“调用 LLM 分析”可能产生 API 费用。** 确认后会向你配置的在线模型发送选中的证据文本。429 或 5xx 最多自动重试 2 次，没有无限重试。一次新的分析不是读取历史结果，可能再次计费。

历史结果再次打开不会再次调用 LLM。想重新查看已有分析，应使用“历史分析”，无需重新点“调用 LLM 分析”。页面上的费用确认和历史操作是两条独立流程。

## 9. 历史分析

通过本地证据校验的成功结果自动保存到数据目录下：

```text
data/analyses/<analysis_id>.json
```

结果顶部显示“已自动保存”和时间。刷新页面、关闭网站或第二天重新启动服务后，在“历史分析”点击“查看结果”即可；页面标注“已保存结果 · 不会调用 LLM”。同一论文对重新分析会保留新的独立版本，不覆盖旧结果。

- **导出 JSON**：包含完整安全结果、已选证据和证据分组，适合备份或后续处理。
- **导出 Markdown**：包含结论、方法变化和最终引用的原文证据，适合 Obsidian、Zotero 附近的笔记或综述材料；不会铺开所有未引用的预览证据。

历史记录不保存 API Key、请求头、原始模型响应或 reasoning 内容。即使原 PDF 被移动或删除，保存的 quote 仍可查看；要回到完整论文阅读，仍需找到原 PDF。

分析超时、截断、解析或证据校验失败时不会生成成功记录。分析成功但磁盘保存失败时，页面仍保留结果并提示保存失败；此时刷新后不能保证恢复，先保留当前结果并检查磁盘空间或权限。

4.5 之前仅存在浏览器里的结果不会自动补入历史。历史为空时显示“还没有已保存的分析结果”。

## 10. 每次重新打开 PowerShell

`$env:...` 设置的环境变量可能只存在当前 PowerShell session。关闭窗口后，新窗口不一定继承它们；服务也需要从配置正确的窗口启动。已运行的服务不会自动获得另一个窗口后来设置的变量，调整后应重启服务。

从 `app` 运行下面的安全检查，只显示模型、兼容选项和“是否有 Key”，不会打印 API Key 内容：

```powershell
..\env\python.exe -c "from intern_atlas.config import get_settings; s=get_settings(); print(s.llm_models[0], s.llm_thinking_mode, s.llm_reasoning_effort, s.llm_json_mode, bool(s.llm_api_key))"
```

最后的 `True` 只说明已配置非空 Key，不等于认证或联网测试成功。这条检查不调用模型。

| 配置项 | 用途 |
| --- | --- |
| `LLM_BASE_URL` | 兼容 Chat Completions 的服务地址，通常包含 `/v1` |
| `LLM_API_KEY` | 在私密的本地配置中设置，不写进仓库或分享的截图 |
| `LLM_MODEL` | 使用的模型名称 |
| `LLM_TIMEOUT_SECONDS` | 单次请求等待时间，默认 120 秒 |
| `LLM_THINKING_MODE` | 留空、`disabled` 或 `enabled` |
| `LLM_REASONING_EFFORT` | 留空、`none`、`low`、`high` 或 `max` |
| `LLM_JSON_MODE` | 留空/`false`/`0` 为关闭；`true`/`1` 为开启 |

兼容选项默认不向所有供应商强行发送；只在当前服务支持时配置。`thinking` 和 `reasoning_effort` 可以同时发送。若已有 `S4S_LLM_MODELS` 或 `LLM_MODELS`，它们优先于单独的 `LLM_MODEL`；检查命令显示的第一个模型就是当前 lineage client 使用的模型。

无需为了查看本地 PDF、Preview 或历史而填写 Key。不要打印整个 settings 对象或把 `.env` 提交到 Git。

## 11. 常见问题

| 问题 | 先检查什么 |
| --- | --- |
| PDF 不显示 | 文件是否直接位于当前 `data_dir/papers`，是否为 PDF；确认数据目录配置，然后刷新页面 |
| 扫描 PDF 无法解析 | 尝试在 PDF 阅读器里选中文字；当前无 OCR，只有图片的 PDF 不会生成伪证据 |
| 没有 methods evidence | 先在单篇“查看证据”中检查章节和正文。标题映射是轻量规则；方法也可能被分到 background/unknown，或未进入有限预算 |
| LLM output truncated | 输出达到当前 4,000 tokens 上限，截断 JSON 不会被保存。检查服务支持的 thinking/reasoning/JSON 设置和模型；重新分析可能计费 |
| API Key 未配置 | 用第 10 节命令检查最后一项；从配置正确的同一窗口重启服务。本地查看和历史仍可使用 |
| GitHub / 网络错误 | GitHub push 或认证错误不会让本地已保存结果消失。发现和在线 LLM 的联网错误只影响对应操作，不等于本地 PDF/历史功能损坏 |
| 为什么 analysis 是 uncertain | 关系证据可能缺少 A/B 任一方的实质文字、只有引用或元数据，或具体比较不完整；先展开“查看依据”和不确定性说明 |
| 为什么 evidence 很多 | PDF 按段落提取，单篇原始证据可能很多；模型上下文仍受每篇 20 块和字符预算限制，结果默认按需展开 |
| 为什么 PDF 删除了，历史还能看 | 成功记录保存了实际引用的 quote 和位置，读取历史不需要重新解析 PDF |
| 启动时报数据库无法打开 | `serve` 以只读方式打开已存在的数据库；检查 `--db` 路径，首次可按第 3 节用 `--no-llm` 初始化 |
| 没有历史记录 | 可能尚无 4.5 之后保存成功的分析，或当前数据目录不同；分析失败不会保存，保存失败会有提示 |

需要报告问题时，提供论文标题、页面错误和不含秘密的配置检查结果即可，不要发送 API Key 或原始 Gateway 请求头。
